隔了两个月再打开一门课，最浪费时间的做法是从 `part-01.md` 第一个字重读。复习材料针对的就是这个场景：**先找回状态，再决定从哪里继续。**

## 调用方式

```text
/lathe 复习 <slug>
/lathe review <slug>
```

## 它生成什么

文件命名为**最新部分编号 + 1 并附 `-review` 后缀**——已有 `part-01`~`part-03` 时，生成的是 `part-04-review.md`。内容包括：

- **逐部分回顾**——每部分构建了什么、核心概念、关键数字；
- **自测：间隔检索**——5–8 个**不给答案**的问题，覆盖各部分关键概念；
- **重跑检查点**——摘录各部分的检查点命令与预期输出，供你在本地重新执行；
- **学习目标回顾**——对照 `goal` 说明已经建立起来的能力；
- **还可以继续深入的方向**——3–5 个延伸方向，想继续时直接 `/lathe 续写 <slug>`。

## 它不做什么

复习的边界很清楚：

- **不引入新内容**——只重组课程里已有的东西。
- **不改变课程方向与状态**——已完结的课程复习后仍然显示完结；想继续学要用续写，续写会自动撤销完结。
- **不参与验证**——`/lathe 验证` 会跳过所有 `-review` 文件。

复习材料会计入 `metadata.json` 的 `parts` 数组，在 `/lathe 列表` 里以 *（复习）* 标注，所以它不会和教学部分混淆。

## 和面试文档的区别

两者容易混，实际定位完全不同：

| | 复习材料 | 面试文档 |
|---|---|---|
| 面向 | 课程**内**的回顾 | 课程**外**的独立产物 |
| 文件 | `<教程目录>/part-NN-review.md` | `<slug>.md` 或 `interview.md`，可放在别处 |
| 组织 | 按部分逐条回顾 | 按 Part 分章，每条要点是「一句话回答 → 展开 → 追问点 → 我的项目里」 |
| 计入 `parts` | 是 | 否 |
| 参与验证 | 否 | 否 |

两者可以同时存在、互不干扰。面试前突击用后者，见[面试要点文档](/docs/lathe/interview/)。
