## 教程可以跨多个会话续写吗

可以。每次调用 `/lathe 续写`（或 `/lathe extend`）时，AI 会从 `metadata.json` 和已有部分文件中读取完整上下文，因此即使换了会话甚至换了 AI 模型，也能无缝续写。

## 可以在不同的 AI 工具之间切换使用吗

技能采用标准的 Agent Skills 布局（`SKILL.md` 入口 + `references/` 子目录），这是 Anthropic 提出的开放规范，多个 AI 工具均已支持：

| 客户端 | 用户级目录 | 项目级目录 | 状态 |
| --- | --- | --- | --- |
| QoderWork / QoderWork CN | `~/.qoderwork/skills/` | `.qoderwork/skills/` | ✅ 已测试 |
| Reasonix（DeepSeek 原生终端 Agent） | `~/.reasonix/skills/` | `.reasonix/skills/` 或 `.claude/skills/` | ✅ 机制已验证（原生支持 SKILL.md 标准，自动注入 `references/` 内容，配合 DeepSeek V4 使用） |

在未列出的其他工具（如 Qoder、Qwen Code 等）中可能无法正常工作，使用前建议先小规模验证。

> 教程数据由 `~/.lathe/config.json` 管理（默认目录 `~/others/lathe_tutorials/`，也支持多路径存储），与具体客户端无关——在 QoderWork 和 Reasonix 之间切换时，教程、标签、验证结果完全共享。

## 验证失败了怎么办

先看 `verify-result.json` 里失败部分的 `failed_step` 和 `error` 字段定位问题。常见原因：

- 代码块中的代码不完整或有遗漏——v0.5.4 起，`runnable` 块里出现 `...` 会被直接视为代码不完整；
- 检查点命令的预期输出与实际不符；
- 前置条件遗漏了某个工具；
- `expected_failure` 块**意外成功**（它期望的是非零退出或特定错误）；
- 改动面预检没过：`changed_interfaces` 里的调用点在教程中没有对应代码块，或 `runnable` 块里还留着旧签名。

注意：**版本冲突类问题（示例声明的版本与代码使用的特性不匹配）不会直接记为失败**——验证时会自动检测，并在你确认后修复，修复记录在 `fixes` 字段。其他问题修好教程后重新运行 `/lathe 验证`。

流程细节见[验证教程可用](/docs/lathe/verify/)。

## 升到 v0.5.4，旧教程要迁移吗

不需要强制迁移。

- **代码块**：没有类型标记的旧块一律按 `runnable` 处理。只有当旧教程里的片段或 `...` 被验证误判时，给那一个块补上 `fragment` / `exercise` 标记就行，不必改正文。
- **metadata**：缺的字段（`changed_interfaces`、`_needs_backfill` 等）按已有内容推断，并在下次写回时补齐；实在推断不出来的会记进 `_needs_backfill` 等你手动确认，不会中止任何操作。
- **写作规则**：讲透优先、代码完整性这些约束作用在新生成和续写的部分上，不会回头改写你已经有的部分。

想彻底干净一遍：先备份教程目录，把 `...`、填空和片段盘点一次补上类型标记，再补 metadata 缺失字段，最后跑一次全量验证（`/lathe 验证 <slug>` 要求全量，或直接把 `changed_interfaces` 改一下触发快照不一致）。

## 如何修改已生成教程的内容

直接在编辑器里改 `part-NN.md` 即可。改完建议重新运行 `/lathe 验证` 确认可用性。

如果你改的是**旧部分**，记得顺手处理连续性摘要：把 `continuity.updated_through` 改成一个较小的值，或直接删掉整个 `continuity` 字段，下次续写就会重新全文读取并重建摘要。也可以直接告诉 AI「我改过前面的部分」。

## Voice 会影响教程的准确性吗

不会。Voice 仅控制语气和风格（是否使用第一人称、幽默程度、句子节奏等）。教程的准确性、研究纪律、引用规范和验证规则是不变量，不受 Voice 影响。

## 如何查看所有已生成的教程

直接用 `/lathe 列表`（或 `/lathe list`），教程会按编程语言分组，每门课逐部分列出并附验证状态。

也可以直接浏览教程基础目录（默认 `~/others/lathe_tutorials/`），或用标签筛选：

```bash
# 查找包含特定标签的教程
grep -rl '"compilers"' ~/others/lathe_tutorials/*/metadata.json
```

## 教程分散在多个目录，还能统一管理吗

可以，分两种情况：

- **配置文件丢失（首次重建）**：调用 `/lathe` 时回答「已经使用过」并提供所有教程位置，技能会扫描验证并逐个登记到 `tutorial_paths`。
- **配置已存在，但新增了未登记的教程**（手工拷贝、`git clone`、目录移动、跨机器同步）：用 `/lathe 扫描` 把它们登记进来，并顺带清理已失效的条目——这是配置建立之后发现教程的**唯一入口**。

之后生成新教程时也可以随时指定不同的保存位置。`/lathe 列表` 会枚举所有已登记目录，非默认目录下的教程会标注所在路径。

## 误删了某门课的 metadata.json 怎么办

运行 `/lathe 列表` 会看到该教程被标注为 *⚠️ metadata 缺失*。随后对它执行任一写入型操作（如 `/lathe 标签 <slug>` 或 `/lathe 续写 <slug>`），技能会自动检测到缺失，从 `part-*.md` 正文推断各字段（标题、语言、工具版本、来源等），展示推断结果、经你确认后重建索引——**教程正文本身不会被动到**。

## 面试文档和复习材料有什么区别

- **复习材料**（`part-NN-review.md`）是**课程内的回顾**——逐部分回顾、自测题、重跑检查点，计入 `parts`，`/lathe 列表` 会标注 *（复习）*。
- **面试文档**（`<slug>.md` 或 `interview.md`）是**课程外的独立文件**——一个 slug 一个文档，按 Part 分章，每条要点给出「一句话回答 → 展开 → 追问点 → 我的项目里」的面试表达，**不计入 `parts`**、不参与验证，`/lathe 列表` 也不会把它当成教程部分。

两者可以同时存在，互不干扰。

## 面试文档会漏掉早期的部分吗

不会。技能在**任何面试写入之前**都会先算一次遗漏集合（教学部分中尚无分段的那些）：

- **单 Part 触发**（如 `/lathe 面试 raft-go part-03`）或**续写建文档**时，会先问你**补写全部**还是**只写当前**（默认补写全部）；
- **整课程触发**且文档**已存在但不完善**时，会先给出待补清单并要你确认；
- 文档**不存在**或**已完善**时**不打扰**。

另外，这门课已经有面试文档时，续写会自动同步本部分——不必每次手动补。

## 面试文档为什么不为复习材料生成分段

因为复习材料（`part-NN-review.md`）本身就是**回顾性内容**——对已有部分的重新组织（逐部分回顾、自测题、重跑检查点），不含新的教学要点，为它建分段只会产生重复条目。同理，收尾的**总结部分**也不产出分段（它是全课程回顾 + 知识图谱 + 目标对照）。跳过这两类文件时不提示、不报错。

## 意图不明确时会发生什么

当你只输入 `/lathe`，或者输入的内容含糊到无法判断意图时，AI **不会默认生成教程**，而是展示一个操作选项菜单（生成 / 续写 extend / 验证 verify / 提问 ask / 标签 tag / 语气 voice / 扫描 scan / 列表 list / 面试 interview），让你选择要执行的操作。复习 review 通过关键词显式触发。
