这两项都不影响教程内容本身，但决定了课程好不好找、读起来合不合口味。放在一起讲。

## /lathe 标签：让课程可被检索

### 调用方式

```text
/lathe 标签 <slug>
/lathe tag <slug>
```

### 标签规范

AI 会选择 2–5 个小写、可复用的标签，覆盖三个维度：

| 维度 | 示例 |
| ---- | ---- |
| **语言/运行时** | `go`、`rust`、`zig`、`python` |
| **领域** | `compilers`、`databases`、`audio`、`networking` |
| **核心技术** | `consensus`、`dsp`、`parsing`、`concurrency` |

优先选择能与其他教程自然分组的通用标签，避免过于具体的一次性标签——标签的价值在于横向对比，`raft-election-go-part1` 这种就没有意义。

### 三种操作

- **设置标签**：完全替换 `tags` 数组
- **添加标签**：追加到现有数组并去重
- **移除标签**：从现有数组中删除

结果保存在 `metadata.json` 的 `tags` 字段。语言标签还额外被 `/lathe 列表` 用来做分组（缺失时从工具链和主题推断）。

> 顺带一提：`/lathe 标签` 也是**误删 `metadata.json` 之后最省事的自愈入口**——它是写入型操作，会触发索引重建。

## /lathe 语气：定制教程的文风

### 内置 Voice

| Voice | 特点 | 适用场景 |
| ------------------- | --------------------- | ------------- |
| **plainspoken**（默认） | 直接、精确、不虚构人格。平实散文，信任读者 | 大多数技术教程 |
| **companion** | 温暖、幽默、第一人称，像键盘旁的老朋友 | 入门教程、需要亲和力的场景 |
| **craftsman** | 从容的匠人师傅。散文式构建，长短句交替，类比贯穿，先讲「为什么」再讲「怎么做」 | 需要深度讲解设计决策的教程 |

### 调用方式

```text
/lathe 语气 [名称]
/lathe voice [name]
```

例如 `/lathe 语气 terse`、`/lathe voice field-notes`。

### 创建流程

1. **选择名称**——提供或确认一个简短的 slug（如 `terse`、`socratic`）。
2. **风格访谈**——AI 会问：正式 ↔ 随意？密集 ↔ 疏朗？冷峻 ↔ 温暖？人称用第一人称、协作式还是非人称？幽默程度是无、克制还是活泼？以及一个反向问题：**这种 voice 绝不应该像什么？**
3. **起草规范**——生成包含「风格与调性」「避免」「校准对比」三章的 markdown 文件。
4. **展示并确认**——给出完整草稿，按你的反馈迭代到批准为止。
5. **持久化**——写入 `<TUTORIALS_DIR>/voices/<名称>.md`。

### 使用与管理

创建后，在生成教程时指定即可：

```text
/lathe 用 Rust 构建解析器，使用 terse voice
```

voice 名称会记在 `metadata.json` 里，`/lathe 续写` 自动继承，不会写着写着换腔调。

- **查看已有 voice**：浏览 `<TUTORIALS_DIR>/voices/` 目录
- **删除 voice**：直接删掉对应的 `.md` 文件
- **内置 voice 不可覆盖**：`plainspoken`、`companion`、`craftsman` 保留为内置

> 注意：`voices/` 始终位于**默认基础目录**（`tutorials_base_path`）下，不跟随单门课的位置。原因见[教程存在哪里](/docs/lathe/storage/)。

### 安全护栏

技能会拒绝创建这几类 voice：冒充真实人物、虚构资历或权威背书、试图把 AI 生成内容伪装成人类撰写。

### 语气会影响准确性吗

不会。Voice 只控制语气和风格（是否用第一人称、幽默程度、句子节奏等）。教程的准确性、研究纪律、引用规范和验证规则是不变量，不受 voice 影响。
