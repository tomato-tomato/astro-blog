生成是整个技能体系的核心入口，其他所有操作都围绕它产出的那份 `part-01.md` 和 `metadata.json` 展开。

## 调用方式

```text
/lathe <主题描述>
```

例如：

```text
/lathe 用 Zig 构建数字合成器
/lathe 用 Rust 实现一个键值存储
/lathe 用 Go 构建 Raft 共识算法
```

## 工作流程

调用后 AI 会按下面八步走。理解这几步，就知道它为什么要问你那些问题。

### 1. 解析配置

从 `~/.lathe/config.json` 读取配置。配置缺失时先问你是第一次使用还是已生成过教程（见[教程存在哪里](/docs/lathe/storage/)）。

### 2. 一轮分组提问

AI 用**一条消息**集中收集写作前需要的全部信息，不做多轮往返：

- **保存位置（每次生成都问）**：默认提议配置里的默认目录，可指定其他路径。
- **教程 slug**：由主题推导一个 kebab-case 短名称并展示给你确认——它是目录名，也是你此后调用其他所有操作的凭据。
- **经验水平**：初学者、有一定了解、还是相关领域有经验？记录为 `experience_level`，后续续写直接沿用，不再重复询问。
- **主题新颖度**：这个主题对你是全新领域、有相邻经验、还是已经熟悉？记录为 `topic_novelty`，默认按经验水平推断。它决定检索预算、地基章节与陷阱密度；配额只约束知识点数量，不会为了配额删掉必要解释。
- **语气（voice）**：可选 `plainspoken`（默认，平实精确）、`companion`（陪伴式）、`craftsman`（工匠式），或用 `/lathe 语气` 创建的自定义 voice。不选就用默认，此时不加载任何额外文件；选了非默认项才按需加载对应规范。
- **澄清问题**：仅在主题宽泛时出现，最多一个。
- **仓库**：是否针对特定代码仓库（URL 和分支）。
- **工具链版本与学习目标**：例如「我将基于 **Go 1.22** 来写——可以吗？」。同时 AI 会基于主题和你的回答提炼一句可评估的**学习目标**（`goal`）一并请你确认——它是后续续写时「目标达成回顾」与收尾完结的判定基准。

某项未作答时，AI 采用合理默认值并告知，不再追问。

### 3. slug 与目录冲突检查（写作之前）

确认 slug 后、开始研究之前，AI 会检查保存位置下是否已存在同名目录。**已存在时绝不覆盖**，而是先识别它是什么（标题、部分数、状态），然后给你三个选项：换一个 slug 新建 / 改为续写那个教程 / 取消。

> 相近主题（如「用 Rust 写 CLI 工具」与「Rust 命令行应用」）极易推导出同一个 slug，这道检查就是为了避开覆盖已有教程。若该 slug 已登记在**其他**目录，AI 也会一并告知——可能是教程被移动过，可以用 `/lathe 扫描` 校正登记。

### 4. 确定教程语言

正文语言默认跟随你的对话语言，也可显式指定（如「用英文写」）。结果记在 `metadata.json` 的 `language` 字段，后续续写、提问自动沿用。

### 5. 选定风格主锚点

按主题匹配一位标杆作者作为主锚点（如分布式系统 → `sam-who`、编译器 → `nystrom`），其 id 记入 `metadata.json` 的 `style_anchor`。后续续写直接沿用该 id，不再重新加载整张标杆表——既保证节奏一致，也省开销。

### 6. 研究主题

AI 通过网络搜索查阅权威来源（官方文档、论文、源代码），确保内容基于真实资料而非模型记忆。研究采用**摘要优先**策略：先从搜索结果标题与摘要提取事实，只有摘要不足以支撑某个关键事实时才做定向全文抓取。

**检索预算按主题新颖度分级**（生成与续写用同一套预算）：

| 主题新颖度 | 搜索次数 | 全文抓取 |
|---|---|---|
| 熟悉 | 3 | 1–2 |
| 相邻 | 5 | 3 |
| 全新 | 8 | 5–6 |

一次搜索可携带 1–4 条 query，来源条数不设上限。

预算之外还有一条**来源下限**：每个部分至少打开或确认 3 个实际来源，其中至少 1 个是官方 / 一手来源——**搜索调用数不等于来源数**，搜了八次但一个页面都没打开不算数。来源优先级是：官方文档 / 规范 / RFC / 源码 / changelog > 高质量独立文章 / 论文 > 博客 / 问答；关键事实要能对应到具体来源，没有来源就标 `[!UNVERIFIED]`。

同时执行**版本-特性一致性检查**：示例代码用到的特性必须在锁定版本下成立（例如 Rust 的 edition 与代码语义要匹配），不确定时查官方 changelog。

> 如果当前会话没有网络工具，AI 会提前告知，并在关键声明处标记 `[!UNVERIFIED]`。

### 7. 生成第一部分

AI 在内部完成预检（选择控制性示例、确定章节结构与 `course_plan`、校验版本-特性一致性）后撰写 `part-01.md`，同时写下三处状态：H1 之后的**「未验证」横幅**、检查点之后的**「本部分结束时的文件状态」**、「接下来」里的**「下一部分起始状态」**（这三处是给续写和验证用的，见[教程文件结构](/docs/lathe/file-structure/)）。

然后按**配额矩阵**执行**交付前自检**：六项讲透检查（定义、动机、用法、例子、边界、可观察结果）、代码完整性、知识点数量、练习、来源、版本、术语锚定与一致性。每节一次，最多两轮——第二轮只查跨章节项和刚改过的地方，不反复全文通读。

### 8. 存储教程

把 `part-01.md` 和 `metadata.json` 写入你确认的位置，在 `tutorial_paths` 中登记，然后告知你：

> **教程已保存**到 `~/others/lathe_tutorials/raft-go/`。
> 这是第一部分。要添加更多部分，调用 `/lathe 续写 raft-go`。
> 验证是可选的：调用 `/lathe 验证 raft-go`。无论是否验证，代码都必须完整；验证只执行 `runnable` / `expected_failure` 块和检查点，片段、练习与文本块会跳过。
> 要对某个部分提问，调用 `/lathe 提问 raft-go part-01.md`。

## 一篇合格教程长什么样

生成阶段遵循的质量标准，也是你读教程时可以拿来验收的清单：

- **控制性示例**：贯穿始终的具体产物（如「一个 4 声部减法合成器」），不用 `foo` / `bar`。
- **概念锚定**：重要概念除详细介绍外，还会从你已知的知识体系引申讲解，锚点随你回答的经验水平调整。
- **自适应深度**：按主题新颖度调整检索预算、地基章节和陷阱密度——新主题多讲地基和陷阱，熟悉主题保持精简。
- **讲透优先**：每个构建节要讲清定义、动机、用法、例子、边界和可观察的验证结果；需要类比、对照或展开时就写，**不因篇幅配额删减**。配额只约束知识点数量，不限制解释长度、类比句数、标注总数或代码行数。
- **覆盖与一致性**：每个核心知识点至少有一个练习或可观察结果；代码里的符号、数字、API 与正文及 `fixed_numbers` 一致。
- **代码完整性**：代码块按 `runnable` / `fragment` / `exercise` / `text` / `output` / `expected_failure` 标记；运行必需代码不得用 `...` 省略；改 API 或签名时给出改动面表，并至少有一个集成检查点。
- **可读性拆分**：单部分正文（不含代码与来源）超过约 10,000 中文字符，或单个 `runnable` 超过约 100–120 行时，**优先拆分**而不是压缩解释；大代码按逻辑段拆，测试单独成块。
- **最终状态**：每部分列出新增 / 修改的文件、「下一部分起始状态」和「本部分不覆盖」，降低你自己拼装和 AI 续写漂移的成本。
- **具体数字**：采样率、缓冲区大小、页面大小都写实际值，避免模糊的「很快」「很大」。
- **内联引用**：关键事实旁直接附来源链接。
- **检查点**：每个部分末尾有可执行的验证命令和预期输出。
- **标注系统**：用 `> [!PREDICT]`、`> [!RECALL]`、`> [!HEADS-UP]` 等标注增强学习效果；标注按需使用、不设总数上限，每个都要对应一个具体知识点或真实陷阱（速查见[教程文件结构](/docs/lathe/file-structure/)）。
- **风格标杆**：按主题场景匹配一位主锚点作者，侧重其长项来指导写作节奏与章节结构；但**风格锚点不覆盖讲透原则**——节奏可以学，该讲的不能省。完整标杆体系在技能包的 `references/style-benchmarks.md`。
