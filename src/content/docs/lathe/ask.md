看教程时最常见的中断是：某一步为什么这样设计、换个写法行不行、这个参数为什么是这个值。直接问 AI，它往往把整个主题从头给你讲一遍——内容对，但和你正在读的这门课没关系。

`/lathe 提问` 的差别就在于：**它先读你这门课的对应部分，再用课里的示例、数字和术语回答。**

## 调用方式

```text
/lathe 提问 <slug> [part] <你的问题>
/lathe ask <slug> [part] <your question>
```

`part` 参数宽松匹配：`part-01.md`、`part-01`、`1` 都可以；也可以**直接省略**，AI 会根据问题内容自动定位最相关的部分，无法判断时列出部分清单让你选。

例如：

```text
/lathe 提问 raft-go part-01
为什么用环形缓冲区而不是 channel？

/lathe ask raft-go 1
为什么用环形缓冲区而不是 channel？

/lathe 提问 digital-synth-zig
如果滤波器截止频率超过奈奎斯特频率会怎样？（省略 part，自动定位）
```

## 回答原则

- **扎根于本教程**——使用教程中相同的示例、数字和术语，不另起一套。
- **指向具体位置**——优先说「看 §3 里的 `process_buffer` 循环」，而不是从零推导。
- **对缺口诚实**——如果问题暴露了教程的错误或含糊之处，会直接说明，而不是绕过去。
- **对话式**——保持会话，可以继续追问。

## 这是个只读操作

提问不写入任何文件，也不会改变课程状态。你可以放心在任何阶段使用它，包括已经完结的课程。

如果提问之后你想把结论沉淀下来，有两条路：直接手工编辑对应的 `part-NN.md`（改完建议重新[验证](/docs/lathe/verify/)），或者继续[续写](/docs/lathe/extend/)把问题推进成下一部分。
