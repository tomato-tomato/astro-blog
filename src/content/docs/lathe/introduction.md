这一册是 [Lathe](https://github.com/devenjarvis/lathe) 提炼成的那个技能的使用说明。但说明本身解释不了它为什么长成现在这样——为什么有个「验证教程」，为什么续写要能读本地代码，为什么每次生成前要先问一轮。所以前言想先把这条来路讲清楚：**技能里每一个看起来多余的动作，背后都是一次具体的不顺。**

## 学 Rust 这件事，我试过的路子都不太顺

- **看官方文档**，看不下去。不是文档写得不好，是我拿它当「从头读到尾」的材料在用。
- **Rustlings**，学到后面把前面忘了。练题是散的，没有一条把知识点串起来的主线。
- **花钱买课程**，和看文档一样，还是读不完。
- **问 AI**，得到的永远是「十个适合练手的项目」这种清单，没有一个系统性的东西能让我照着走完整门语言。

中间也认真看过几个专门做「AI 学习」的方向。清华开源的 [openMAIC](https://open.maic.chat/) 和千问小讲堂都是讲课模式，更适合按知识点听课的学生（顺便一句牢骚：千问小课堂目前只在手机端能找到入口，网页端和桌面端都没有😂）。Google 实验室的 Learn your way 我很早就关注过，想把 Rust 官方教程喂进去让它生成课程，结果一直卡在让我填一个表格，进不去😩。

真正让我上头的是网页版 Gemini 的学习模式：问答式、及时反馈、讲得通俗，那种成就感很像有个在线家教坐在旁边。但它给我的是**一次次独立的解答**，不是一门有结构、能续写、能复习、最后还能拿去面试的课程。我想要的是后者。

## 遇到 Lathe

有天逛 [Zeli](https://zeli.app/zh) 刷到了 Lathe 这个项目，看完介绍惊为天人😲——它要做的正好是我缺的那块：把一个主题变成一套**有起点、能续写、可验证**的动手教程，而不是一篇长文。这里得再次感谢写这个工具的人🙏，它确实让我找到了适合自己的学 Rust 的方法。

兴奋完，问题立刻变得很具体：**这套东西在国内怎么跑起来。**

## 从「先跑起来」到「做成技能」

最初的想法是最省事的：拿 DeepSeek 和 相关工具，照着 Lathe 仓库里的使用教程直接用。试下来两个字：麻烦。它原本是一条 CLI 工作流，环境要求、命令、状态文件都得我自己伺候。

那就换个思路——它的工作流本质上是一堆**写给模型看的规则**，能不能把这些规则提炼成一个 skill，让编码助手自己照着执行？我让 AI 出了第一版：由 Qwen 3.7 Max 读 Lathe 的代码改写而来。仓库第一次提交是 2026-06-15。

执行端选了最开始选的 QoderWork：有免费额度、能用、操作方便，而且能直接在界面里看到生成的教程。学习路线是拿网页 kimi 总结的一批 Rust 练手项目，第一门课是一个 todo CLI。到这里，「能用了」。

那个时候，Kimi 网页版还没限 Token, QoderWork 还有免费额度，所以也就先适配 QoderWork。后来，优化、自测、使用 大部分都交给了 DeepSeek。（为啥？因为便宜🤪）所以你可以看到在 Releases 页面存在 pre-release，对于这种类型其实是已经完成但是还没自己用过，一般用过觉得还行才会发布 release。目前自己会使用在 Qoder、Workbuddy、DeepSeek Harness、Reasonix 这几个agent中。

## 两件外部的麻烦，反而定了后来两轮的取向

**第一件是额度。** 2026-08-11 那天记录里写了一句：QoderWork 已经没有每天打卡的免费额度了。学完第一门课，后续生成得转移到别的端（我选的是 Reasonix）。要开始花钱之后，想做的第一件事不是加功能，而是算清楚**一次生成本来要读进去多少东西**——后面那轮分级触发、预检与自检去重、配额前置、加载集从 47.6 KB 压到 41.5 KB，动机全部出自这里。省钱的约束最后变成了架构约束，这大概是这个技能最不像「玩具」的地方。

**第二件是限制本身。** Anthropic 对国内用户的各种限制，以及用国外优秀模型要跨过的一道道门槛，把我的选择面压得很窄：只能用国内能用、好用、并且最好不用花太多钱的工具。这个约束从一开始就决定了它是「一个 skill + 一个编码助手」的形态，而不是又一个要装的服务。

## 这一册怎么读

这一册描述的是 **v0.5.4**，技能仍在迭代，所以偶尔会和最新版有点出入；版本号在每篇里都会写明，左栏目录最后一行也会标出「本指南对应技能版本」。

第一次上手按 [Lathe 是什么](/docs/lathe/overview/) → [下载与安装](/docs/lathe/install/) → [教程存在哪里](/docs/lathe/storage/) 读一遍就够；日常操作查对应的那篇，学完之后看 [复习材料](/docs/lathe/review/) 和 [面试要点文档](/docs/lathe/interview/)；[教程文件结构](/docs/lathe/file-structure/) 和 [常见问题](/docs/lathe/faq/) 放在最后当参考。

源仓库在这里：[tomato-tomato/my-rust-lathe-courses](https://github.com/tomato-tomato/my-rust-lathe-courses)，技能包从 [Releases](https://github.com/tomato-tomato/my-rust-lathe-courses/releases) 下载，本册就是那份 `docs/skills-tutorial.md` 按版本重排而来的。有问题欢迎提 Issue。

最后留一句老实话：只是照着生成的教程把代码一行行敲完，敲完就翻篇，那不论用什么工具都不会有效果——这种「光秃秃的执行」很容易让人误以为自己在学。我现在会带着问题敲：这一段为什么这样写、换一个写法会怎样，先问一句再动手。一开始没什么感觉，但同一个知识点被后面的部分反复捞回来几次，熟悉感才慢慢长出来。Lathe 技能在这件事上只帮一个忙：让这条学习的路不断——不在它最贵的时候断，也不在我最懒的时候断。
