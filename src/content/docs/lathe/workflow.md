前面每个操作都单独讲过，这一页把它们串成一条真实的使用轨迹。以「用 Go 学 Raft」为例。

## 第一步：创建配置（首次使用）

```text
用户：/lathe 用 Go 构建 Raft 共识算法

AI：检测到还没有配置文件。这是你第一次使用 Lathe，还是之前已经生成过教程？

用户：第一次使用

AI：教程默认存储在 ~/others/lathe_tutorials/，要使用其他位置吗？

用户：默认就好
```

> 如果你之前已生成过教程（可能分散在多个目录），回答「已经使用过」并提供这些位置，技能会扫描验证后写入配置，让所有已有教程重新可见。

## 第二步：一轮分组提问并生成

```text
AI：已创建配置。开始前请一次性确认几件事：
    1. 本教程将保存到 ~/others/lathe_tutorials/（默认目录），要换个位置吗？
    2. 你在分布式系统领域的经验水平——初学者、有一定了解、还是相关领域有经验？
    3. 这个教程是独立教程，还是针对特定仓库？
    4. 我将基于 Go 1.22 来写；学习目标定为"掌握 Raft 核心机制（Leader 选举、
       日志复制、安全性）并用 Go 从零实现"——可以吗？

用户：默认位置，有一定了解，独立教程，Go 1.22 和学习目标都可以

AI：（研究主题中……以摘要优先策略查阅了 Raft 论文、Go 标准库文档等来源，
      并校验示例代码特性与 Go 1.22 兼容）
    （生成 part-01.md 和 metadata.json，正文语言跟随对话记为 zh-CN，
      并在配置的 tutorial_paths 中登记 raft-go 的位置）

    教程已保存到 ~/others/lathe_tutorials/raft-go/。
    要添加更多部分，调用 /lathe 续写 raft-go。
```

细节拆解见[生成第一部分](/docs/lathe/generate/)。

## 第三步：续写更多部分

```text
用户：/lathe 续写 raft-go 这一部分实现 Leader 选举

AI：（阅读已有教程）
    你是否有已完成的本地项目代码？如果有，提供项目路径可以让我基于你当前的
    实际代码来续写下一部分课程。

    1. ✅ 提供项目路径 — 我会读取项目代码，基于当前进度续写
    2. ⏭️ 跳过 — 基于教程中描述的状态续写

    请回复编号，或直接输入项目路径。

用户：2

AI：（研究 Leader 选举，生成 part-02.md）
    已添加 part-02.md。可以调用 /lathe 验证 raft-go 验证。
```

## 第四步：验证教程

```text
用户：/lathe 验证 raft-go

AI：（版本一致性预检：比对锁定版本、配置声明与代码特性，未发现冲突）
    （在验证工作区 .lathe-verify/ 中逐步执行，运行检查点命令）
    验证结果：
    - part-01.md：✓ 通过
    - part-02.md：✓ 通过
    教程验证全部通过！metadata.json 状态已同步为 verified。
```

> 若预检或执行中发现版本冲突（例如示例声明的 edition 与代码语义不匹配），AI 会展示冲突详情和两个修复方案，征得你同意后修复并重新验证。

## 第五步：提问和打标签

```text
用户：/lathe 提问 raft-go part-02
     为什么选举超时要随机化？

AI：在 part-02.md 的「选举超时」章节中，随机化是为了防止
    两个候选者同时发起选举导致的活锁……

用户：/lathe 标签 raft-go

AI：已为教程设置标签：["go", "distributed-systems", "consensus", "raft"]
```

提问时 `part` 也可以省略（`/lathe ask raft-go 为什么选举超时要随机化？`），AI 会自动定位相关部分。

## 第六步（可选）：收尾完结与复习

```text
用户：/lathe 续写 收尾 raft-go

AI：（阅读全部部分并对照学习目标评估达成度）
    （生成总结部分：全课程回顾、知识图谱、目标对照、练习方向、寄语）
    课程已完结，status 已标记为 completed。
    想继续精进时直接 /lathe 续写 raft-go 即可重新开放。

# 之后若久未学习想先找回状态（不会改变完结状态）：
用户：/lathe 复习 raft-go

AI：已生成 part-NN-review.md：逐部分回顾、自测问题、
    可重跑的检查点命令，以及继续深入的方向。
```

## 第七步（可选）：生成面试文档

```text
用户：/lathe 面试 raft-go

AI：检测到面试文档尚不存在。
    面试文档将保存到 ~/others/lathe_interview/raft-go.md，要换个位置吗？

用户：（回车）

AI：已创建 raft-go.md，并按教学部分逐个写入面试分段：
    第一部分（12 条）、第二部分（9 条）……
    后续续写会自动同步新部分；也可随时 /lathe 面试 raft-go 补齐。
```

> 中途才想起来写也可以——技能会先检测哪些教学部分还没有分段，再问你是**补写全部**还是**只写当前**。

## 第八步（可选）：创建自定义语气

```text
用户：/lathe 语气 socratic

AI：（进行风格访谈，起草 voice 规范）
    这是 socratic voice 的草稿……是否满意？

用户：很好

AI：已保存到 ~/others/lathe_tutorials/voices/socratic.md。
    下次生成教程时可以指定：/lathe <主题>，使用 socratic voice
```

## 这条链路的几个特点

- **每一步都可跳过**：验证是可选的，面试文档是可选的，语气是可选的。只有「生成 → 续写」是主干。
- **状态都在文件里**：换会话、换客户端、换机器，只要 `~/.lathe/config.json` 和教程目录还在，就能接着学；目录丢了就用 [`/lathe 扫描`](/docs/lathe/scan-and-list/) 找回。
- **成本随课程变长而下降**：第一次续写要全文读一次建立摘要，之后每次只读摘要 + 最后一部分；列表也永不读正文。
- **写入范围始终很小**：每个操作只碰自己那几类文件，删除教程、清理工作区这类破坏性动作一律留给你手工做。
